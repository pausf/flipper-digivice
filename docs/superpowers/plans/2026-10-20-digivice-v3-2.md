# Digivice v3.2 (roster, evolution, feeding and calls) Design and Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. One fresh, short-lived agent per task: the usage budget is tight, so a task must be doable from this document and the files it names, nothing else.

**Goal:** Give the pet the full original lifecycle: feeding in visible bites with two foods, a 28-monster roster drawn procedurally, a hidden-counter evolution tree on Color-like stage timers (with a failure form and a redemption path), and a call alert that turns neglect into care mistakes. All of it on a v4 save that keeps the pet already on the device.

**Architecture:** Two new pure-C modules sit next to `digivice_rules.c`: `digivice_roster.c` (one table: name, stage, attribute, time-in-stage per form) and `digivice_evolution.c` (the tree: which form comes next from the hidden counters). The state grows from 116 to 140 bytes with the counters, the strength hearts ("vigor"), the call windows and `stage_since`. Stages go from 4 to 7 (Egg, Baby I, Baby II, Rookie, Champion, Ultimate, Mega), so the battle tables grow to 7 entries. Sprites stay procedural: the 8 trail monsters already drawn for v3.1 are reused as roster forms, the other 20 are new `DvPen` draw functions in `digivice_draw_roster.c`, dispatched from `digivice_draw_form`. Every task compiles and is shippable on its own; a bestiary preview screen (Task 4) makes forms visible long before evolution reaches them.

**Tech Stack:** C11, Flipper Zero firmware (furi, gui/canvas, notification, saved_struct), u8g2 `u8g2_font_4x6_tf`, host `cc` for tests, GitHub Actions (`fbt`) on the private remote `digivice`.

**Inputs (source of truth for names):** research `docs/superpowers/research/2026-10-16-vpet-digivice-research.md` (2.3 calls, 2.4 overfeeding, 3.1 timers, 3.2 branching, 9.3, 9.4, 9.7); mockups `docs/superpowers/mockups/v3/v3-bestiario.html` (roster, tree, looks) and `v3-cuidados.html` (bites, refusal, call); status `docs/superpowers/v3-status.md`; previous spec and plan `docs/superpowers/specs/2026-10-19-digivice-v3-1-battle-expedition-design.md`, `docs/superpowers/plans/2026-10-19-digivice-v3-1.md` (conventions); code under `applications/services/digivice/` and `applications/main/digivice/`.

# Part 1: Spec

## Scope

In: feeding rework, 28-monster roster plus the failure form, 7 stages with timers, hidden counters and the evolution tree, state v4 with migration, battle scaling for Ultimate and Mega, calls and care-mistake rework.
Out (v3.3): cities, easter eggs, NIDO and companions, link battles (so PRISMAR and BALIZA are drawn and listed but unreachable), a "seen forms" dex gate.

## Rules (exact numbers; every one lives in `digivice_config.h`)

**Feeding.** Two foods, chosen on a picker screen (Left/Right, OK).

| Food | Effect | Refused when |
|---|---|---|
| Meat (CARNE / MEAT) | hunger +1 (max 4), corruption -5 | hunger is 4 |
| Protein (PROTEINA / PROTEIN) | vigor +1 (max 4), `strength` +2, corruption -5 | vigor is 4 |

A refusal changes nothing except the hidden `overfeed` counter: it counts +1 once, then the food's "arm" bit stays off until that meter drops below max (a heart must drain before the next refusal counts). Vigor starts at 2, loses 1 heart per 4 awake hours (`DIGIVICE_VIGOR_DECAY_S`). Each meal is eaten in 3 bites; the refusal is a head-shake.

**Stages and timers** (wall clock since `stage_since`; Egg keeps the 300 s hatch).

| Stage | Forms | Time in stage |
|---|---|---|
| Egg | BYTEEGG | 300 s |
| Baby I | PIPO (line A), CHISPI (line B) | 10 min |
| Baby II | OREJIN, COLIX | 12 h |
| Rookie (Novato) | KORNO, CHIPKO, ESTATIK, MOKOBIT, and the failure form CHARCO | 24 h (CHARCO: 36 h) |
| Champion | ARIETE, ECOLOBO, VAMPIXEL, CERROJO, BUHOSCAN, FUZZCAN, SILBAPO, CHATARRO | 36 h |
| Ultimate (Supremo) | LANZERO, WYVOLT, FANGOREY, BOVEDAX, KOLOSO | 48 h |
| Mega | AUREOLA, DRAKSTAT, ORAKULO, NULARCA | no limit |
| Special | PRISMAR (fusion), BALIZA (secret) | drawn only, unreachable in v3.2 |

**Hidden counters** (all reset to 0 on every real evolution; lifetime `wins`/`losses` carry over): `evo_mistakes` (care mistakes from calls), `train_count` (successful trainings), `battles` and `wins_stage` (Win or Lose results in this stage; Fled and Draw do not count), `overfeed`, `night_owl` (sleeps with the light left on).

**Tree** (conditions are checked in the listed order once the timer has elapsed; a branch that finds no match falls through):

| From | To | Condition |
|---|---|---|
| BYTEEGG | PIPO or CHISPI | 50/50 from the state rng |
| PIPO / CHISPI | OREJIN / COLIX | timer only |
| OREJIN | KORNO, else ESTATIK | `evo_mistakes` <= 2, else >= 3 |
| COLIX | CHIPKO, else MOKOBIT | `evo_mistakes` <= 2, else >= 3 |
| KORNO | ARIETE / ECOLOBO / VAMPIXEL / CHARCO | train >= 24 and mistakes <= 1 / train 12 to 23 / mistakes >= 2 / none matched |
| ESTATIK | FUZZCAN / SILBAPO / CHARCO | train >= 16 / overfeed >= 3 / none |
| CHIPKO | CERROJO / BUHOSCAN / CHARCO | train >= 24 / night_owl >= 3 / none |
| MOKOBIT | CHATARRO / CHARCO | train >= 16 / none |
| ARIETE, ECOLOBO | LANZERO | battles >= 12 and wins >= 60% |
| VAMPIXEL, FUZZCAN | WYVOLT | same |
| CERROJO, BUHOSCAN | BOVEDAX | same |
| CHATARRO | KOLOSO | same |
| SILBAPO, CHARCO | FANGOREY | same (CHARCO is the redemption path) |
| LANZERO / WYVOLT / BOVEDAX / KOLOSO | AUREOLA / DRAKSTAT / ORAKULO / NULARCA | `evo_mistakes` <= 1, battles >= 10, wins >= 80% |
| FANGOREY | NULARCA | area 8 boss defeated (`cleared & 0x80`) |

If the requirement of a Champion or Ultimate form is not met when the timer ends, the pet stays and is re-checked every tick (nothing is lost).

**Battle scaling** (indexed by stage: Egg, Baby I, Baby II, Rookie, Champion, Ultimate, Mega): power `{0, 10, 14, 20, 40, 56, 76}`, VIRUX power `{24, 24, 24, 24, 46, 64, 84}`, shot size `{2, 2, 2, 3, 5, 7, 10 (beam)}`.

**Calls and care mistakes.** A call starts the moment hunger or vigor reaches 0 (only while awake: both decay only awake, so a sleeping pet never starts one) and lasts 10 awake minutes (`DIGIVICE_CALL_WINDOW_S` 600). Answering means getting that meter above 0 (meat for hunger, protein for vigor). If the window runs out: +1 care mistake for that call (two calls at once cost two), no re-call until the meter was refilled and emptied again. LED amber double blink plus two short buzzes when a call starts (silent while asleep); the FEED icon blinks inverted and the home screen shows the attention bubble. Mistake bookkeeping: a call mistake raises both `care_mistakes` (the v2.1 sickness driver, reset by a full cure) and `evo_mistakes` (the evolution counter). Poop (6 h dirty) and light left on asleep still raise `care_mistakes` (v2.1 sickness rules stay) but no longer raise `evo_mistakes`; the light raises `night_owl` instead.

## State v4 (saved_struct version 0x04, 140 bytes)

The v3 layout (116 bytes) stays a frozen prefix, `DigiviceStateV3`. Appended at offset 116: `uint8_t vigor, call_flags, feed_flags, evo_mistakes, train_count, battles, wins_stage, overfeed, night_owl, reserved4[3]; uint16_t call_hunger_s, call_vigor_s; uint32_t stage_since, vigor_acc_s;`. Load chain: v1 -> v2 (`migrate_v1`), v2 -> current (`migrate_v2`, which now also applies the v4 defaults), v3 -> current (`migrate_v3`), v4 as is. Forms keep their ids: new forms are appended to the enum, so a v3 pet is valid under v4 untouched and is only moved onto the new tree in Task 9 (`upgrade_legacy`).

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Task 2 is the v4 state alone, before feeding. | Overfeed and vigor need persistent fields; shipping them first keeps every later task tiny and gives the device its migration early. |
| D2 | Form ids: new forms are appended (ids 8 to 35); the 6 legacy forms (BITLING, BYTEMON, TAGDRAKE, WAVEDRAKE, BEAMDRAKE, PLUGDRAKE) keep their ids and are mapped at load in Task 9. VIRUBYTE stays. One BYTEEGG serves both lines. | No save reshuffle; Tasks 4 to 9 can ship with the old tree still evolving the pet. |
| D3 | The 8 trail monsters (ESTATIK, CHIPKO, KORNO, MOKOBIT, FUZZCAN, VAMPIXEL, SILBAPO, CHATARRO) are reused as roster forms via `digivice_draw_foe`. | 8 of 28 sprites for free, already approved. |
| D4 | Legacy mapping at load: BITLING to PIPO, BYTEMON to KORNO, TAGDRAKE to CERROJO (Cifrado), WAVEDRAKE to ARIETE (Portador), BEAMDRAKE to FUZZCAN (Ruido), PLUGDRAKE to CHATARRO (Nulo). `stage_since` restarts at load time, counters at 0. | Attributes are preserved, so the pet's battle identity is intact; the user's Bitling gets a visible 10 min evolution. |
| D5 | CHARCO has the Rookie stage (power 20, no boss gate) and a 36 h timer. | A failure form should be weak; the redemption is winning 12 battles at 60% with it. |
| D6 | PRISMAR is attribute Portador (the mockup shows Portador plus Cifrado; battle uses one). | The attribute triangle is single-valued. |
| D7 | EXP no longer drives evolution. Hacker deeds still grant EXP and data. `DIGIVICE_ROOKIE_EXP` and `DIGIVICE_CHAMPION_EXP` are deleted in Task 9; the profile bar shows the stage timer. | Color-like timers replace the EXP thresholds. |
| D8 | `digivice_rules_player_type` (Hacker data type of the pet) now derives from the roster attribute: Cifrado NFC, Portador Sub-GHz, Ruido IR, Nulo USB. | The old form-to-type table dies with the old forms. |
| D9 | `night_owl` is the existing "light left on asleep" event (the research's sleep disturbance); waking is already refused while asleep. | No new input path. |
| D10 | Calls start on the empty transition only, count awake seconds only, and fire the LED once. No countdown is shown. | Deterministic across 60 s and catch-up ticks; the countdown would need per-minute publishes. |
| D11 | Head-shake is a horizontal jitter of the pet (+-3 px, every 2 frames), not a mirror flip. | `digivice_draw_form` has no flip parameter; the mockup's intent (a "no") is kept at no flash cost. |
| D12 | Sleeping foe-based forms draw as idle plus the existing zzz overlay; `pen_eye` gains a closed-eye Sleep pose. | The 8 foe sprites never had a sleep frame. |
| D13 | Calls clear when the meter is refilled by feeding. Training does not refill vigor. | One answer per call, no hidden path. |
| D14 | Evolution at most one stage per `digivice_rules_evolve` call; after a long offline gap, later stages follow on the next ticks with timers restarted from the moment of each evolution. | Keeps the tick path linear; no free stage skipping. |
| D15 | Training count thresholds (24, 12, 16) come straight from the mockup. Each training costs a hunger heart, so 24 in 24 h is demanding. They are `DIGIVICE_EVO_TRAIN_*` constants; if device play shows them out of reach, tune the numbers, not the code. | Faithful to the approved tree, trivially tunable. |
| D16 | Flash ceiling for v3.2: at most **+40 KB (40,960 bytes) of `text + data`** over the v3.1 build (v3.1 is +23.8 KB over v2.1). Expected: roster about +10 KB, rules and UI about +6 KB. | Sprites stay procedural. |

# Part 2: Plan

## Global Constraints

- Work on the new branch `digivice-v3.2`, created from `digivice-v3.1` in Task 1. Never commit to `main`, `digivice-v2.1` or `digivice-v3.1`.
- Never run `./fbt` locally and never build. CI (`.github/workflows/digivice.yml` on remote `digivice` = `pausf/flipper-digivice`) runs the host tests and `./fbt COMPACT=1 DEBUG=0 updater_package` on every push of a `digivice-*` branch. The controller decides when to push (after any task it can afford: each task leaves a green, shippable build) and watches CI; a task executor never pushes. Executors run only the host tests (`applications/services/digivice/test/run.sh`).
- Shell tools: `rg`, `fd`, `bat`, `eza`, `sd` only; never `grep`, `find`, `cat`, `ls`, `sed`. Do not use `sd` for replacements containing `$`.
- Every tuning number lives in `applications/services/digivice/digivice_config.h`.
- `digivice_rules.c/.h`, `digivice_expedition.c/.h`, `digivice_battle.c/.h`, `digivice_i18n.c/.h`, `digivice_roster.c/.h`, `digivice_evolution.c/.h` and `digivice_config.h` stay pure C with no furi includes and are host-tested by `applications/services/digivice/test/run.sh` (`cc -std=c11 -Wall -Wextra -Werror`, binaries to `$TMPDIR`). Pure rules are written test-first.
- Source files are ASCII-only. Spanish accents live only in `digivice_i18n.c`, as the UTF-8 escape macros already there (`A_ACUTE`, `E_ACUTE`, `I_ACUTE`, `O_ACUTE`, `U_ACUTE`, `N_TILDE`, `EXCL_INV`, `QUES_INV`). The i18n host test scans every digivice source for non-ASCII bytes. Monster names are proper nouns and are never translated.
- fbt builds with `-Wall -Wextra -Werror -Wstrict-prototypes -Wredundant-decls -Wdouble-promotion -Wundef` including `-Wformat-truncation` and `-Wswitch`: size every `snprintf` buffer for the worst case (u32 = 10 digits, u16 = 5, u8 = 3, every `%s` at its full UTF-8 byte length) and add every new enum value to every `switch` over that enum (the app has switches over `DigiviceScreen`).
- u8g2 coordinates are unsigned 16 bit: never pass a negative x or y to `canvas_draw_*`; use the clipped `digivice_draw_line`, `digivice_draw_box`, `digivice_draw_dot` or keep coordinates on screen.
- Conventional Commits. No `Co-Authored-By` and no AI attribution anywhere (this overrides any default attribution). Stage explicit paths only (`git add <path>...`); never `git add .` or `git add -A`. `web/graphql.stg`-style untracked files elsewhere must stay untouched.
- Repo style: 4-space indent, `if(` / `for(` / `while(` / `switch(` with no space, column limit 99, comments only on non-obvious code, matching the neighbours' density. `ponytail:` comments are always in English.
- The service explicitly lists its sources in `applications/services/digivice/application.fam`: every new `.c` there must be added (Tasks 4 and 9). `applications/main/digivice/application.fam` lists none (fbt globs that folder).
- Stock-file diff stays limited to digivice files, `applications/services/digivice/test/run.sh` and `.github/workflows/digivice.yml`. No Bandai names, art or sprites.
- RAM: the service stack is 2 KB. The load chain holds at most one old-version temporary at a time (v1 56 B, v2 84 B, v3 116 B) beside the 140 B state. `digivice_rules_same_visible` keeps copying one state. No new large locals in the service.
- Save format: magic `0xD1`, version `0x04`, 140 bytes. `DigiviceStateV1` (56), `V2` (84) and `V3` (116) are frozen copies that never change. A migrated pet's `last_tick` and `stage_since` are re-anchored to now at load, so it earns no free paces, care penalties, calls or evolution time for the time spent on the old firmware.
- Flash ceiling: **+40,960 bytes of `text + data` over the v3.1 build.** The v3.1 baseline is the "Report firmware size" line of the latest green CI run on `digivice-v3.1` (Task 1 records it). If a push shows a delta above 30 KB before Task 7 is done, stop and drop the special forms (PRISMAR, BALIZA) and the legacy-sprite code; above 40 KB, stop and re-scope.
- Every firmware-touching task ends with a "CI/device check (controller)" step. Device checks use the CI artifact `digivice-update-package` of the pushed commit, flashed over USB (`scripts/selfupdate.py -p /dev/cu.usbmodemflip_<name>1 <update.fuf>` or qFlipper), only after CI is green. The last task's push is a "Step: push (controller only)".

    bool meat = food == DigiviceFoodMeat;

    uint8_t level = meat ? s->hunger : s->vigor;

#include "digivice_evolution.h"
#include "digivice_config.h"
#include "digivice_roster.h"

static bool record_ok(const DigiviceState* s, uint8_t min_battles, uint8_t pct) {
    return s->battles >= min_battles &&
           (uint32_t)s->wins_stage * 100U >= (uint32_t)s->battles * pct;
}

static uint8_t baby_next(const DigiviceState* s) {
    bool good = s->evo_mistakes <= DIGIVICE_EVO_MISTAKES_GOOD;
    switch(s->form) {
    case DigiviceFormPipo:
        return DigiviceFormOrejin;
    case DigiviceFormChispi:
        return DigiviceFormColix;
    case DigiviceFormOrejin:
        return good ? DigiviceFormKorno : DigiviceFormEstatik;
    case DigiviceFormColix:
        return good ? DigiviceFormChipko : DigiviceFormMokobit;
    default:
        return DigiviceFormNone;
    }
}

// Conditions are checked in the order of the tree; a Rookie that matches none becomes CHARCO.
static uint8_t rookie_next(const DigiviceState* s) {
    uint8_t t = s->train_count;
    switch(s->form) {
    case DigiviceFormKorno:
        if(t >= DIGIVICE_EVO_TRAIN_HI && s->evo_mistakes <= 1) return DigiviceFormAriete;
        if(t >= DIGIVICE_EVO_TRAIN_MID && t < DIGIVICE_EVO_TRAIN_HI) return DigiviceFormEcolobo;
        if(s->evo_mistakes >= 2) return DigiviceFormVampixel;
        break;
    case DigiviceFormEstatik:
        if(t >= DIGIVICE_EVO_TRAIN_LO) return DigiviceFormFuzzcan;
        if(s->overfeed >= DIGIVICE_EVO_OVERFEED) return DigiviceFormSilbapo;
        break;
    case DigiviceFormChipko:
        if(t >= DIGIVICE_EVO_TRAIN_HI) return DigiviceFormCerrojo;
        if(s->night_owl >= DIGIVICE_EVO_NIGHT_OWL) return DigiviceFormBuhoscan;
        break;
    case DigiviceFormMokobit:
        if(t >= DIGIVICE_EVO_TRAIN_LO) return DigiviceFormChatarro;
        break;
    default:
        return DigiviceFormNone;
    }
    return DigiviceFormCharco;
}

static uint8_t champion_next(const DigiviceState* s) {
    if(!record_ok(s, DIGIVICE_EVO_ULT_BATTLES, DIGIVICE_EVO_ULT_PCT)) return DigiviceFormNone;
    switch(s->form) {
    case DigiviceFormAriete:
    case DigiviceFormEcolobo:
        return DigiviceFormLanzero;
    case DigiviceFormVampixel:
    case DigiviceFormFuzzcan:
        return DigiviceFormWyvolt;
    case DigiviceFormSilbapo:
    case DigiviceFormCharco: // the redemption path
        return DigiviceFormFangorey;
    case DigiviceFormCerrojo:
    case DigiviceFormBuhoscan:
        return DigiviceFormBovedax;
    case DigiviceFormChatarro:
        return DigiviceFormKoloso;
    default:
        return DigiviceFormNone;
    }
}

static uint8_t ultimate_next(const DigiviceState* s) {
    if(s->form == DigiviceFormFangorey) {
        // The final boss (area 8) must have fallen.
        return (s->cleared & 0x80) ? DigiviceFormNularca : DigiviceFormNone;
    }
    bool ok = s->evo_mistakes <= DIGIVICE_EVO_MEGA_MISTAKES &&
              record_ok(s, DIGIVICE_EVO_MEGA_BATTLES, DIGIVICE_EVO_MEGA_PCT);
    if(!ok) return DigiviceFormNone;
    switch(s->form) {
    case DigiviceFormLanzero:
        return DigiviceFormAureola;
    case DigiviceFormWyvolt:
        return DigiviceFormDrakstat;
    case DigiviceFormBovedax:
        return DigiviceFormOrakulo;
    case DigiviceFormKoloso:
        return DigiviceFormNularca;
    default:
        return DigiviceFormNone;
    }
}

uint8_t digivice_evolution_next(const DigiviceState* s, uint32_t now) {
    const DigiviceRosterEntry* e = digivice_roster(s->form);
    if(!e || e->stay_s == 0) return DigiviceFormNone;
    if(now < s->stage_since || now - s->stage_since < e->stay_s) return DigiviceFormNone;
    // CHARCO has the Rookie stage but waits a Champion's time and follows the Champion rule.
    if(s->form == DigiviceFormCharco) return champion_next(s);
    switch(e->stage) {
    case DigiviceStageBaby:
    case DigiviceStageBaby2:
        return baby_next(s);
    case DigiviceStageRookie:
        return rookie_next(s);
    case DigiviceStageChampion:
        return champion_next(s);
    case DigiviceStageUltimate:
        return ultimate_next(s);
    default:
        return DigiviceFormNone;
    }
}

bool digivice_rules_evolve(DigiviceState* s, uint32_t now) {
    // The pending cutscene must be acknowledged first or it would be overwritten unseen.
    if(s->evo_from != DigiviceFormNone) return false;
    uint8_t next;
    if(s->form == DigiviceFormByteegg) {
        if(now < s->stage_since || now - s->stage_since < DIGIVICE_HATCH_S) return false;
        next = digivice_rules_rng_pct(s) < 50 ? DigiviceFormPipo : DigiviceFormChispi;

static uint8_t upgrade_form(uint8_t form) {
    switch(form) {
    case DigiviceFormBitling:
        return DigiviceFormPipo;

    default:

    }
}

bool digivice_rules_upgrade_legacy(DigiviceState* s, uint32_t now) {
    uint8_t form = upgrade_form(s->form);
    uint8_t prev = upgrade_form(s->prev_form);
    uint8_t from = upgrade_form(s->evo_from);
    bool changed = form != s->form || prev != s->prev_form || from != s->evo_from;
    s->form = form;
    s->prev_form = prev;
    s->evo_from = from;
    if(changed) {
        s->stage_since = now;
        s->train_count = 0;
        s->battles = 0;
        s->wins_stage = 0;
        s->overfeed = 0;
        s->night_owl = 0;
        s->evo_mistakes = 0;
    }
    return changed;
}
