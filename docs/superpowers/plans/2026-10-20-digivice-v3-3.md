# Digivice v3.3 (easter eggs, capture, NIDO, cities) Design and Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. One fresh, short-lived agent per task: the usage budget is nearly exhausted, so a task must be doable from this document and the files it names, nothing else. Sonnet is enough for every task.

**Goal:** Add the three approved v3 "fun" features on top of the v3.2 pet already flashed on the device: nine hand-drawn homage partners that show up as special encounters roughly every 5 battles (behind the build flag `DIGIVICE_EASTER_EGGS`), a capture sequence that fills a NIDO (nest) and lets one caught partner walk beside the pet, and a CIUDAD setting that swaps the trail background for a city skyline with landmarks and an exclusive city monster.

**Architecture:** One state bump (v4 140 B to v5 148 B, 8 appended bytes: `caught`, `companion`, `city`, `special_count`) lands first and alone (Task 2), so every later task is small. Two new pure-C modules sit beside the rules and are host-tested: `digivice_homage.c` (flagged: names, odds, pick, capture) and `digivice_city.c` (city names, monster stats, pick). Special encounters reuse the existing trail encounter: `enc_foe` gains two code ranges (`0x10..0x18` partner, `0x20..0x24` city monster) and `DigiviceBattle` gains a `foe_class`, so battle, rewards and the app need no new encounter kind. All art is procedural pen code, as in v3.1 and v3.2: partners in `digivice_homage_draw.c` (flagged, drawable at half size for companions), landmarks and city monsters in `digivice_draw_city.c`. Every task compiles, passes the host tests and is shippable: a not-yet-drawn partner or city monster falls back to a generic blob or an existing trail-foe sprite.

**Tech Stack:** C11, Flipper Zero firmware (furi, gui/canvas, notification, saved_struct), u8g2 `u8g2_font_4x6_tf`, host `cc` for tests, GitHub Actions (`fbt`) on the private remote `digivice`.

**Inputs (source of truth):** status `docs/superpowers/v3-status.md`; approved mockups `docs/superpowers/mockups/v3/v3-easter-eggs.html` (the 9 partners, banner, capture, NIDO) and `v3-ciudades.html` (landmarks, monsters, event banner); previous plan `docs/superpowers/plans/2026-10-20-digivice-v3-2.md` (conventions, copied below); code under `applications/services/digivice/` and `applications/main/digivice/`.

**Mapping to the requested T1 to T5:** requested T2 (easter eggs) is Tasks 2 to 5 here, T3 (capture, NIDO, companion) is Tasks 6 and 7, T4 (cities) is Tasks 8 to 10, T5 (verification and push) is Task 11. The split exists only so each task is one short agent run and one green build.

# Part 1: Spec

## Scope

In: special encounters with 9 homage partners, capture, NIDO, companion, state v5, CIUDAD setting with 5 skylines, 7 landmarks and 5 city monsters.
Out: link battles, weekly event calendar (the mockup's AUTO calendar row; CIUDAD here is a fixed choice), secret-code or 100-win unlocks (the build flag is the unlock), a loader for user-provided sprites.

## Rules (exact numbers; every one lives in `digivice_config.h`)

**Build flag.** `DIGIVICE_EASTER_EGGS` defaults to 1 in `digivice_config.h` (`#ifndef` guard, so `-DDIGIVICE_EASTER_EGGS=0` or editing one line turns it off). Off: `digivice_homage.c`, `digivice_homage_draw.c` and `digivice_app_nido.c` compile to stubs, no partner is ever picked, `enc_foe` partner codes are sanitised away, the NIDO is unreachable and no partner name or sprite is linked in. The save keeps `caught` and `companion` either way (a later build with the flag on gets them back). Partner names are other people's trademarks: this build stays private, the flag is OFF for anything distributed.

**Special encounter (partner).** Rolled once each time a trail encounter spawns (the existing 3% per pace, guaranteed by pace 50), only when the pet is Rookie or above (`DIGIVICE_SPECIAL_MIN_STAGE` 3). Odds by `special_count` (battles finished since the last partner, 0 to 4): `{0, 10, 20, 40, 100}` percent, so the first encounter after a partner is never one, and the fifth is guaranteed. `special_count` goes +1 on every Win or Lose that was not itself a partner fight (Fled and Draw do not count), saturating at 4, and resets to 0 the moment a partner spawns. The partner is drawn from the ones not yet caught; once all 9 are caught, from all 9. The roll uses a hash of `rng` and never advances `rng`, so every v3.2 encounter sequence is unchanged when no special is possible.

**Partner fight.** An ordinary trail fight (3 hits, charge meter, aim, shield) with: power `stage_power[pet stage] * 12 / 10` (`DIGIVICE_HOMAGE_X10` 12), the partner's own attribute, shot size = the pet's shot size. EXP is the trail formula times `DIGIVICE_SPECIAL_EXP_X` (2). Intro: the existing 16-frame lead-in with the banner `!ENCUENTRO ESPECIAL!` (blinking, replaces the "!" bubble) and the rainbow-then-magenta LED; the service plays the same rainbow LED when the partner spawns while the app is closed (silent while asleep, like every encounter).

**Capture.** Resolved atomically in `digivice_rules_battle_result` on a Win against a partner (the app only plays the reveal). Already in the nest: result Friend, no roll, +`DIGIVICE_FRIEND_EXP` (15) EXP. Otherwise roll 0..99 from the state rng against `min(95, 60 + 5 * mood)` (mood 0..4, so 60 to 80): below it, Caught (`caught` bit set; if there was no companion, this one becomes it); else Escaped and `special_count = DIGIVICE_HOMAGE_RETRY` (2), so it comes back within 3 encounters. Lose, Fled and Draw against a partner also set `special_count = 2`; declining at the lead-in changes nothing (the encounter just expires).

**Reveal (app, 60 frames of the 100 ms clock, `DIGIVICE_CAPTURE_FRAMES`).** Frames 0 to 11 the partner is dizzy (Hurt pose, sparkle ring); 12 to 39 a dashed ring closes on it from radius 22 to 8; at frame 40 an inverted flash, then Caught: the partner vanishes, sparkles and star, banner `!CAPTURADO!`, the evolution jingle, panel line `NUEVO EN EL NIDO`; Escaped: it walks off to the right at 2 px per frame under the banner `SE ESCAPO` (with its accent). OK/Back is ignored until frame 60. Friend skips the ring and shows the normal victory with the panel line `YA ES TU AMIGO`.

**NIDO.** FICHA (profile) screen, Left (Right already opens the bestiary). A room 128x64: floor at row 47, a window, a rug (dither) and a lamp; caught partners idle at half size on a 5+4 grid (upper row feet at y 31, lower row y 47), asleep (Sleep pose, zzz) during the sleep hours. Left/Right moves the brackets over the caught ones, OK makes the highlighted one the companion (OK again on the companion clears it), Back returns to FICHA. Empty nest shows a hint line. Panel: name, attribute, and `COMPANERO` when it is the companion.

**Companion.** The chosen partner, drawn at half size (the same sprite code with every coordinate halved), walks 20 px behind the pet on the home view (foot row 50, following the pet's walk with a 6-frame lag; asleep: sleeping beside it), stands 24 px left of the pet on the Hike screen, and stands 22 px left of the pet during the encounter lead-in. Never on the progress-strip trail view (it draws a marker, not the pet sprite).

**Cities.** Setting CIUDAD in AJUSTES between MODO and REINICIAR: NINGUNA, BARCELONA, MADRID, VALENCIA, SEVILLA, BILBAO (Left, Right or OK cycles). `city` 0 means none. Effects, when `city` is 1 to 5:
- Trail background (Expedition, Hike and the battle lead-in) is the city skyline instead of the area scenery: the same sky, day/dusk/night rules and Null Core exception are dropped (a city is always lit by the real clock), generic building blocks on the far layer scrolling at 1/4 speed, two landmarks on the mid layer at 1/2 speed on a 192 px loop, street dots on the near layer at 1x.
- Landmarks (simplified original silhouettes): BCN Sagrada Familia and Torre Gloriès; MAD Puerta de Alcalá and Cuatro Torres; VLC Ciudad de las Artes (the dome and the helmet); SEV Giralda and a crenellated tower; BIO Guggenheim and an arch bridge.
- Exclusive monster: each spawn of a trail encounter rolls `DIGIVICE_CITY_PCT` (30%) to be the city's monster (TRENCADIX Cifrado, MADROSO Portador, TRACALUZ Ruido, GIRALDIN Portador, ESCAMATI Cifrado) instead of a pool foe; checked after the partner roll. It fights as a Champion-tier trail foe (area power times 1.3, shot size 5), EXP times 2, attribute LED, no capture.
- Banner `EVENTO: <CIUDAD>` for the first 30 frames of every trail screen entry and as the lead-in banner of a city monster (blinking, replaces the "!" bubble).

**State v5** (saved_struct version 0x05, 148 bytes). The v4 layout (140 bytes) stays a frozen prefix, `DigiviceStateV4`. Appended at offset 140: `uint16_t caught; uint8_t companion, city, special_count, reserved5[3];`. Load chain: v1 to v2 (`migrate_v1`), v2 to current (`migrate_v2`), v3 to current (`migrate_v3`), v4 to current (`migrate_v4`, new), v5 as is. Every migration applies the v5 defaults (`caught` 0, `companion` 0xFF, `city` 0, `special_count` 0). A migrated pet's `last_tick` is re-anchored to now; `stage_since` is re-anchored only when the old rules were older than v4 (v5 only adds fields, so a v4 pet keeps its evolution timer).

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | State v5 ships first and alone (Task 2) with every field the three features need (`caught`, `companion`, `city`, `special_count`). | The counter must persist across restarts, and Tasks 6 to 10 then never touch the layout. |
| D2 | A partner or city monster is a trail encounter with a different `enc_foe` code, not a new encounter kind; `DigiviceBattle.foe_class` tells them apart. | No new switch cases in `DigiviceEncounterKind`, one `battle_init` branch, the retreat and expiry rules stay. |
| D3 | The odds table is `{0, 10, 20, 40, 100}`, not the mockup's `5, 10, 20, 40`. | A 0 first step keeps every existing v3.2 test deterministic and means a partner never follows a partner; the 5th stays guaranteed. |
| D4 | The special roll hashes `rng` without advancing it. | v3.2 encounter sequences (and their tests) stay byte-identical when no special is possible. |
| D5 | The capture roll lives in `battle_result`, not the app. | One atomic service call: no capture lost to an app exit mid-animation, host-testable. The reveal is only a replay. |
| D6 | The first caught partner becomes the companion automatically. | The feature shows up without finding the NIDO first. |
| D7 | Companions are the same sprite code at half size: partner draw functions go through local wrappers (`hm_*`) that halve coordinates and round sizes up; the shared `digivice_pen.h` is untouched. | A second set of mini sprites would cost 9 more drawings; changing the shared pen would add a branch to every sprite in the firmware. |
| D8 | NIDO is reached from FICHA with Left. | Right is already the bestiary; no new main-menu icon (the icon bar is full: 8 icons). |
| D9 | `RESET PET` keeps `lang`, `mode`, `city`, `caught` and `companion`. | The nest is a collection and the city a setting, not part of one pet's life. |
| D10 | City encounters use the monster's attribute LED, not a city colour. | The mockup's per-city LED colours need intermediate LED levels the notification API lacks; the banner carries the city. |
| D11 | The city skyline ignores the area but keeps the pet's area logic (boss, distance, midway) untouched. | It is only a background; no rule reads it. |
| D12 | City monsters are drawn last (Task 10); Tasks 8 and 9 ship with an interim mapping to trail-foe sprites by attribute (Portador KORNO, Ruido FUZZCAN, Cifrado CHIPKO). | Cities become playable earlier; the interim path is also the flash-ceiling fallback. |
| D13 | Flash ceiling for v3.3: at most **+25,600 bytes (25 KB) of `text + data`** over the v3.2 build. Per-push checkpoints below. | v3.2 was about +30 KB over v3.1; this release is pure procedural art and strings. |

# Part 2: Plan

## Global Constraints

- Work on the new branch `digivice-v3.3`, created from `digivice-v3.2` in Task 1. Never commit to `main`, `digivice-v2.1`, `digivice-v3.1` or `digivice-v3.2`.
- Never run `./fbt` locally and never build. CI (`.github/workflows/digivice.yml` on remote `digivice` = `pausf/flipper-digivice`) runs the host tests and `./fbt COMPACT=1 DEBUG=0 updater_package` on every push of a `digivice-*` branch. The controller decides when to push and watches CI; a task executor never pushes. Executors run only the host tests (`applications/services/digivice/test/run.sh`).
- Shell tools: `rg`, `fd`, `bat`, `eza`, `sd` only; never `grep`, `find`, `cat`, `ls`, `sed`. Do not use `sd` for replacements containing `$`.
- Every tuning number lives in `applications/services/digivice/digivice_config.h`.
- `digivice_rules.c/.h`, `digivice_expedition.c/.h`, `digivice_battle.c/.h`, `digivice_i18n.c/.h`, `digivice_roster.c/.h`, `digivice_evolution.c/.h`, `digivice_homage.c/.h`, `digivice_city.c/.h` and `digivice_config.h` stay pure C with no furi includes and are host-tested by `applications/services/digivice/test/run.sh` (`cc -std=c11 -Wall -Wextra -Werror`, binaries to `$TMPDIR`). Pure rules are written test-first. Tests that depend on the partners are wrapped in `#if DIGIVICE_EASTER_EGGS`; `run.sh` runs the suite a second time with `-DDIGIVICE_EASTER_EGGS=0`.
- Source files are ASCII-only. Spanish accents live only in `digivice_i18n.c`, as the UTF-8 escape macros already there (`A_ACUTE`, `E_ACUTE`, `I_ACUTE`, `O_ACUTE`, `U_ACUTE`, `N_TILDE`, `EXCL_INV`, `QUES_INV`). The i18n host test scans every digivice source for non-ASCII bytes. Monster, partner and city names are proper nouns and are never translated. In this document the accent-bearing Spanish strings are spelled with the macros.
- Partner names (AGUMON and the other eight) appear only in `digivice_homage.c`, its test and this document: never in a header, never in i18n, never in a shared file. Everything else refers to partners by index (`DIGIVICE_HOMAGE_COUNT`, ids 0 to 8).
- fbt builds with `-Wall -Wextra -Werror -Wstrict-prototypes -Wredundant-decls -Wdouble-promotion -Wundef` including `-Wformat-truncation` and `-Wswitch`: size every `snprintf` buffer for the worst case (u32 = 10 digits, u16 = 5, u8 = 3, every `%s` at its full UTF-8 byte length), add every new enum value to every `switch` over that enum (the app has switches over `DigiviceScreen` in draw, input and tick; Task 7 adds `DigiviceScreenNido` to all three), and make every non-`inline` static function used (an unused `static` function is an error: keep sprite helpers `static inline`, and only add a sprite function in the same step that puts it in its table). `-Wundef` means `#if DIGIVICE_EASTER_EGGS` needs the macro defined: every file that tests it includes `digivice_config.h` first.
- u8g2 coordinates are unsigned 16 bit: never pass a negative x or y to `canvas_draw_*`; use the clipped `digivice_draw_line`, `digivice_draw_box`, `digivice_draw_dot`, `digivice_draw_fill_ellipse`, `digivice_draw_fill_triangle` or keep coordinates on screen.
- Conventional Commits. No `Co-Authored-By` and no AI attribution anywhere (this overrides any default attribution). Stage explicit paths only (`git add <path>...`); never `git add .` or `git add -A`. `web/graphql.stg`-style untracked files elsewhere must stay untouched.
- Repo style: 4-space indent, `if(` / `for(` / `while(` / `switch(` with no space, column limit 99, comments only on non-obvious code, matching the neighbours' density. `ponytail:` comments are always in English.
- The service explicitly lists its sources in `applications/services/digivice/application.fam`: every new `.c` there is added in the task that creates it (Tasks 3, 4, 8, 9). `applications/main/digivice/application.fam` lists none (fbt globs that folder).
- Stock-file diff stays limited to digivice files, `applications/services/digivice/test/run.sh` and `.github/workflows/digivice.yml`. No official sprite, ripped asset or traced outline anywhere: every drawing is built from `pen_*` primitives from the written look descriptions.
- RAM: the service stack is 3 KB. The load chain holds at most one old-version temporary at a time (v1 56 B, v2 84 B, v3 116 B, v4 140 B) beside the 148 B state; `digivice_rules_same_visible` keeps copying one state. No new large locals in the service. The Task 2 device check reads "Stack free after load" from the log and must show at least 700 B.
- Save format: magic `0xD1`, version `0x05`, 148 bytes. `DigiviceStateV1` (56), `V2` (84), `V3` (116) and `V4` (140) are frozen copies that never change.
- Flash ceiling: **+25,600 bytes of `text + data` over the v3.2 build.** The v3.2 baseline is the "Report firmware size" line of the latest green CI run on `digivice-v3.2` (Task 1 records it). Expected delta at each controller push: Task 3 +4 KB, Task 4 +8 KB, Task 5 +12 KB, Task 6 +13 KB, Task 7 +16 KB, Task 8 +17 KB, Task 9 +21 KB, Task 10 +24 KB. If a push shows more than 2 KB above its expectation, stop and apply the matching fallback: after Task 5, make companions skip the Hike and encounter screens (home only) and drop the dizzy sparkle ring; after Task 7, drop the NIDO furniture; after Task 9, cut the landmarks to Sagrada Familia, Puerta de Alcala and Giralda plus generic blocks; after Task 10, keep the interim trail-foe sprites for the city monsters (D12). Above 25,600 after all fallbacks: stop and re-scope.
- Every firmware-touching task ends with a "CI/device check (controller)" step. Device checks use the CI artifact `digivice-update-package` of the pushed commit, flashed over USB (`scripts/selfupdate.py -p /dev/cu.usbmodemflip_<name>1 <update.fuf>` or qFlipper), only after CI is green. The last task's push is a "Step: push (controller only)".

uint8_t digivice_homage_pick(DigiviceState* s) {
    if(digivice_rules_stage(s) < DIGIVICE_SPECIAL_MIN_STAGE) return DIGIVICE_ENC_NONE;
    uint32_t r = digivice_rules_hash(s->rng, 0xA6E5);
    if(r % 100 >= digivice_homage_odds(s->special_count)) return DIGIVICE_ENC_NONE;
    s->special_count = 0;
    uint16_t pool = (uint16_t)(~s->caught & DIGIVICE_HOMAGE_MASK);
    if(!pool) pool = DIGIVICE_HOMAGE_MASK;
    uint32_t k = (r >> 8) % (uint32_t)__builtin_popcount(pool);
    for(uint8_t id = 0; id < DIGIVICE_HOMAGE_COUNT; id++) {
        if(!((pool >> id) & 1U)) continue;
        if(k == 0) return (uint8_t)(DIGIVICE_ENC_HOMAGE + id);
        k--;
    }
    return DIGIVICE_ENC_NONE;
}

    if(s->special_count < DIGIVICE_HOMAGE_GUARANTEE) s->special_count++;
}

    uint32_t pct = DIGIVICE_CAPTURE_BASE_PCT + DIGIVICE_CAPTURE_MOOD_PCT * (uint32_t)s->mood;
    return (uint8_t)(pct < DIGIVICE_CAPTURE_MAX_PCT ? pct : DIGIVICE_CAPTURE_MAX_PCT);
}

    if(id >= DIGIVICE_HOMAGE_COUNT) return DigiviceCaptureNone;
    if(s->caught & (1U << id)) return DigiviceCaptureFriend;
    if(roll < digivice_homage_capture_pct(s)) {
        s->caught |= (uint16_t)(1U << id);
        if(s->companion == DIGIVICE_COMPANION_NONE) s->companion = id;
        return DigiviceCaptureCaught;
    }
    s->special_count = DIGIVICE_HOMAGE_RETRY;
    return DigiviceCaptureEscaped;
}

    for(int32_t i = 1; i <= DIGIVICE_HOMAGE_COUNT; i++) {
        uint8_t id = (uint8_t)((from + dir * i + 2 * DIGIVICE_HOMAGE_COUNT) % DIGIVICE_HOMAGE_COUNT);
        if(caught & (1U << id)) return id;
    }
    return from;
}

void digivice_nido_enter(DigiviceApp* app) {
    uint16_t caught = app->state.caught;
    uint8_t first = app->state.companion < DIGIVICE_HOMAGE_COUNT ? app->state.companion : 0;
    app->nido_sel = caught & (1U << first) ? first : nido_step(caught, first, 1);
    digivice_app_set_screen(app, DigiviceScreenNido);
}

void digivice_nido_input(DigiviceApp* app, const InputEvent* event) {
    if(event->type != InputTypeShort && event->type != InputTypeRepeat) return;
    uint16_t caught = app->state.caught;
    switch(event->key) {
    case InputKeyRight:
        app->nido_sel = nido_step(caught, app->nido_sel, 1);
        break;
    case InputKeyLeft:
        app->nido_sel = nido_step(caught, app->nido_sel, -1);
        break;
    case InputKeyOk:
        if(event->type != InputTypeShort || !(caught & (1U << app->nido_sel))) break;
        digivice_set_companion(
            app->digivice,
            app->state.companion == app->nido_sel ? DIGIVICE_COMPANION_NONE : app->nido_sel);
        digivice_get_state(app->digivice, &app->state);
        break;
    case InputKeyBack:
        digivice_app_set_screen(app, DigiviceScreenProfile);
        break;
    default:
        break;
    }
}

```c
static void draw_landmark(Canvas* c, uint8_t kind, int32_t x, Color ink, Color paper, uint32_t frame) {
    switch(kind) {
    case LmSagrada: lm_sagrada(c, x, CITY_GROUND, ink, paper, frame); break;
    case LmGlories: lm_glories(c, x, CITY_GROUND, ink, paper, frame); break;
    /* ...one case per kind, LmNone draws nothing... */
    default:
        break;
    }
}

void digivice_draw_city(
    Canvas* canvas,
    const DigiviceScene* scene,
    uint32_t scroll,
    uint32_t frame,
    bool dark) {
    Color ink = dark ? ColorWhite : ColorBlack;
    Color paper = dark ? ColorBlack : ColorWhite;
    uint32_t far_scroll = scroll / 4;
    int32_t sub = (int32_t)(far_scroll % 6);

    // Far layer: 5 px blocks on a 6 px pitch, outlined, with windows (lit at night).
    for(int32_t k = 0; k < 23; k++) {
        int32_t x = k * 6 - sub;
        uint32_t col = ((far_scroll / 6 + (uint32_t)k) * 6) % CITY_LOOP;
        int32_t top = scene->far[col];
        canvas_set_color(canvas, paper);
        digivice_draw_box(canvas, x, top, 5, CITY_GROUND - top);
        canvas_set_color(canvas, ink);
        digivice_draw_line(canvas, x, top, x + 4, top);
        digivice_draw_line(canvas, x, top, x, CITY_GROUND - 1);
        digivice_draw_line(canvas, x + 4, top, x + 4, CITY_GROUND - 1);
        for(int32_t y = top + 3; y < CITY_GROUND - 2; y += 4) {
            if(dark && ((col + (uint32_t)y) % 3) == 0) continue;
            digivice_draw_dot(canvas, x + 2, y);
        }
    }

    // Mid layer: the two landmarks of the city at half speed on the 192 px loop.
    uint32_t mid = scroll / 2;
    for(int32_t i = 0; i < 2; i++) {
        const DvPlace* place = &panos[scene->city - 1][i];
        int32_t x = (int32_t)((place->x + CITY_LOOP - mid % CITY_LOOP) % CITY_LOOP);
        if(x > 140) x -= CITY_LOOP;
        if(x < -44) continue;
        draw_landmark(canvas, place->kind, x, ink, paper, frame);
    }

    // Near layer: ground line, street dots and a lamp post every 32 px at full speed.
    canvas_set_color(canvas, ink);
    digivice_draw_line(canvas, 0, CITY_GROUND, 127, CITY_GROUND);
    for(int32_t x = 5 - (int32_t)(scroll % 6); x < 128; x += 6) {
        digivice_draw_dot(canvas, x, CITY_GROUND + 3 + (x / 6) % 3);
    }
    for(int32_t x = 12 - (int32_t)(scroll % 32); x < 140; x += 32) {
        digivice_draw_line(canvas, x, CITY_GROUND - 9, x, CITY_GROUND);
        digivice_draw_box(canvas, x - 1, CITY_GROUND - 10, 3, 2);
    }
    canvas_set_color(canvas, ColorBlack);
}
```

`(scene->city - 1)` is safe: `digivice_draw_scene` only calls this when `scene->city` is 1 to 5, and `digivice_scene_init` clamps it. The `panos` table is declared `[DIGIVICE_CITY_COUNT][2]`; Task 9 removes nothing from the interim monster mapping.
